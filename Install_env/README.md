# Mask2Former_Keratin
# Mask2Former one-file installer for Slurm clusters

Installs the **official Mask2Former** (Facebook Research) together with
**Detectron2** and the custom CUDA extension, inside its own conda environment,
with a single `sbatch` command. It is the base for the Adamantinoma histopathology
segmentation project, but nothing in it is project-specific.

No admin rights needed. Nothing is installed system-wide. Every path is
configurable, so it works for any user on any Linux x86-64 Slurm cluster that
has an NVIDIA GPU.

---

## What you get

| Component | Version |
|---|---|
| Python | 3.11 |
| PyTorch / torchvision | 2.1.0 / 0.16.0 (CUDA 12.1 build) |
| CUDA toolkit (inside conda) | 12.1.1 |
| GCC / G++ | 11 |
| Detectron2 | pinned commit `b599f13` |
| Mask2Former | latest `main` (the exact commit is recorded after install) |

The exact result is written to `mask2former_install_info.txt`
(date, GPU, commit, full `pip freeze`). Send that file with any bug report.

---

## Before you start

You need:

1. A Slurm cluster account, with access to a **GPU partition**.
2. **Internet access from the GPU node** (the job downloads from GitHub, conda and PyTorch).
3. An NVIDIA driver that supports CUDA 12.1 (driver 525 or newer).
4. About **25 GB of free disk space** in the place you choose for `BASE` (the conda
   environment alone is around 19 GB). Do not put it in a small home directory.

Not sure about the GPU partition name? Run:

```bash
sinfo -o "%P %G %D"
```

and look for the row whose `GRES` column contains `gpu`. The value in the `PARTITION`
column is what you pass to `-p`. If the name has a `*` (e.g. `gpu*`), leave the `*` out.

## Quick start

```bash
# 1. put install_mask2former.sbatch on the cluster, then:
cd /path/where/you/put/it

# 2. submit (use YOUR partition and GPU request)
BASE=/path/with/plenty/of/space \
  sbatch -p <gpu_partition> --gres=gpu:1 install_mask2former.sbatch

# 3. follow the log (use the job number that sbatch prints)
tail -f slurm-<jobid>.out
```

The install finishes when the end of the log shows:

```
FINAL TEST OK (works from any directory), CUDA: True
DONE
```

A `FutureWarning` from `timm` and an `aau_token ... Permission denied` message from
conda (on some clusters) are harmless.

If you do not set `BASE`, everything goes under your `$HOME`.

### Options (all optional environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `BASE` | `$HOME` | Where conda environments and packages are stored |
| `CODE_PARENT` | `$BASE/codes` | Where the Mask2Former repository is cloned |
| `ENV_NAME` | `mask2former` | Name of the conda environment |
| `CONDA_MODULE` | *(empty)* | Name of the cluster's conda module, e.g. `anaconda3`. If empty and conda is not found, Miniforge is installed under `$BASE/miniforge3` |
| `MAX_JOBS` | `2` | Parallel compile jobs. Set `1` if compilation runs out of memory |

Example with a module and a different location:

```bash
BASE=/scratch/$USER CONDA_MODULE=anaconda3 \
  sbatch -p gpu --gres=gpu:1 install_mask2former.sbatch
```

The script is safe to re-run: an existing environment or repository is reused.

## Using it afterwards

In any new shell, and inside any Slurm job, run one line:

```bash
source $BASE/activate_mask2former.sh
```

That file was generated by the installer and already contains the conda module (if
needed), the environment path, and the activation. The environment also sets
`PYTHONPATH` automatically, so `import mask2former` works **from any directory**.

Minimal training job:

```bash
#!/bin/bash
#SBATCH -p <gpu_partition>
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=8
#SBATCH --mem=48G
#SBATCH -t 24:00:00

set -euo pipefail
source /path/to/activate_mask2former.sh

python your_training_script.py
```

Quick check that it works:

```bash
cd ~
source $BASE/activate_mask2former.sh
python -c "import mask2former, detectron2; print('ok')"
```

On a login node `torch.cuda.is_available()` is normally `False` because there is no
GPU there. That is expected. GPU checks only make sense inside a GPU job.

## What the script does, step by step

1. **Pre-flight checks** (fails early with a clear message): Linux x86-64, a visible
   GPU, and internet access to GitHub.
2. **Conda**: loads your module if you named one; otherwise installs Miniforge.
3. **Environment**: creates it with Python, GCC 11, CUDA 12.1 toolkit and ninja.
4. **Clone** the official Mask2Former and print its commit.
5. **Install** PyTorch (CUDA 12.1 build), the repository requirements, Detectron2 and
   the `MultiScaleDeformableAttention` CUDA extension. These are compiled on the GPU
   node so PyTorch picks the right GPU architecture. Versions are locked with a
   constraints file so later installs cannot silently change PyTorch or NumPy.
6. **Make it usable everywhere**: writes a conda activation hook (sets `PYTHONPATH`),
   the `activate_mask2former.sh` file, and the install record.
7. **Final test** from a neutral directory.

The compile step is the slowest part. On our cluster the whole install took about 6 minutes.

## Troubleshooting

| Message / symptom | Cause | What to do |
|---|---|---|
| `ERROR: no GPU visible on this node` | Submitted without a GPU partition or GPU request | Use `-p <gpu_partition> --gres=gpu:1` (see `sinfo` above) |
| `ERROR: no internet from this node (github.com unreachable)` | Compute nodes are offline | Ask your admins for a proxy, or run the download steps on a login node |
| `sbatch: error: Unable to open file ...` | Wrong directory or file name | `cd` to the folder with the file and check with `ls` |
| `Invalid account` / `Invalid partition` / `Invalid gres` | Names differ on your cluster | Ask your admins for the right account, partition and GPU name |
| Compilation killed / out of memory | Not enough RAM for the CUDA build | Raise `--mem`, or submit with `MAX_JOBS=1` |
| Job stays in `PD` | Waiting for resources | Wait; check with `squeue -u $USER` |
| `ModuleNotFoundError: No module named 'mask2former'` | Environment not activated through the installer's file | Use `source .../activate_mask2former.sh`, or run from inside the repository |
| `conda activate` cannot find the environment | `CONDA_ENVS_PATH` not set in your shell | Use the `activate_mask2former.sh` file, which sets it |
| `Disk quota exceeded` | `BASE` is on a small filesystem | Pick a bigger location with `BASE=...` |
| CUDA errors on a very new or very old GPU / old driver | This baseline is CUDA 12.1 | Check the driver version with `nvidia-smi`; newer GPUs or older drivers may need different versions |

## Remove it completely

```bash
conda deactivate
rm -rf $BASE/.conda/envs/mask2former $BASE/.conda/pkgs \
       $CODE_PARENT/Mask2Former \
       $BASE/activate_mask2former.sh $BASE/mask2former_install_info.txt \
       ~/.cache/pip
```

(Use the same `BASE` and `CODE_PARENT` values you installed with.)

## Known limits

- Tested on one Slurm cluster (NVIDIA H100, using a `4g.47gb` MIG slice). Other
  clusters may need different partition, GPU, module or proxy settings.
- Pinned to Python 3.11, PyTorch 2.1.0 and CUDA 12.1. GPU architectures or drivers
  outside this baseline need their own compatibility check.
- Mask2Former is taken from the upstream `main` branch; the commit is logged so
  you can reproduce the install later.
